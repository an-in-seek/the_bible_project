## 1. 기능 개요

### 1.1 기능 정의

성경 역사 지도는 성경에 등장하는 국가, 민족, 지역, 도시, 산, 강, 이동 경로와 사건을 세계 지도 위에 표시하고, 사용자가 시간 막대를 이동하며 시대별 변화를 확인할 수 있는 인터랙티브 성경 학습 기능이다.

사용자는 지도와 시간의 흐름을 함께 탐색하면서 다음 내용을 직관적으로 이해할 수 있다.

* 성경의 사건이 오늘날의 어느 지역에서 일어났는지
* 시대에 따라 국가와 제국의 영역이 어떻게 변화했는지
* 이스라엘과 주변 민족의 관계가 어떠했는지
* 출애굽, 바벨론 포로, 바울의 전도여행 등이 어떤 경로로 진행됐는지
* 특정 지역에서 어떤 성경 사건과 인물이 등장했는지

---

## 2. 추진 배경

성경 본문은 사건, 인물, 국가와 지역을 중심으로 서술되지만, 현대 독자는 해당 지명의 위치와 지역 간 거리를 직관적으로 이해하기 어렵다.

특히 다음과 같은 학습상의 문제가 존재한다.

1. 동일한 장소가 시대별로 서로 다른 이름으로 등장한다.
2. 성경 시대의 국가와 현대 국가의 경계가 일치하지 않는다.
3. 왕국과 제국의 영토가 시대에 따라 계속 변화한다.
4. 출애굽 경로와 일부 고대 도시의 위치처럼 학계의 견해가 나뉘는 항목이 존재한다.
5. 일반 세계 지도는 현대 국경을 중심으로 구성되어 성경 시대를 설명하기에 적합하지 않다.
6. 성경 본문, 역사적 배경, 지리 정보를 각각 별도로 확인해야 한다.

elseeker는 성경 본문과 학습 기능을 연결하여 이러한 정보를 하나의 연속된 탐색 경험으로 제공한다.

## 3. 기능 목표

### 3.1 핵심 목표

* 성경의 역사적·지리적 배경을 시각적으로 이해할 수 있도록 한다.
* 시간 막대를 통해 국가, 제국, 지역명의 변화를 탐색할 수 있도록 한다.
* 지도상의 장소를 성경 본문, 인물, 사건과 연결한다.
* 검증된 출처와 검수 절차를 기반으로 역사 정보를 제공한다.
* 확정된 사실과 추정·논쟁 중인 내용을 명확하게 구분한다.
* PC와 모바일에서 모두 편리하게 탐색할 수 있도록 한다.

### 3.2 비목표

초기 버전에서는 다음 기능을 제공하지 않는다.

* 현재 위치 기반 길찾기
* 현대 지도 수준의 도로·건물 정보
* 모든 성경 사건의 완전한 수록
* 하나의 연대기를 절대적으로 옳은 해석으로 제시
* 사용자가 직접 역사 경계나 지명을 수정하는 기능
* 3D 지형 및 위성 영상
* 교단별 해석을 하나의 정답으로 통합하는 기능

## 4. 핵심 원칙

### 4.1 성경 본문과 역사 자료 구분

정보를 다음 세 가지 유형으로 구분한다.

1. **성경 본문 기록**

    * 성경에서 직접 확인할 수 있는 사건, 인물, 지명
2. **역사·지리 자료**

    * 역사 문헌, 고고학, 고대 지명 데이터 등으로 확인되는 정보
3. **추정 또는 학설**

    * 위치나 연대, 경로에 복수 견해가 존재하는 정보

사용자 화면에서도 정보 유형을 배지로 구분한다. 이 구분은 확실성 등급과 별도로 관리하여, 성경 본문 기록인지 역사 자료인지, 또는 학설에 가까운 정보인지를 사용자가 즉시 이해할 수 있도록 한다.

예시:

* `성경 본문`
* `역사 자료`
* `유력한 추정`
* `여러 견해 존재`

### 4.2 과도한 정밀도 방지

고대 국가의 경계와 사건 연대는 현대 국경처럼 정확하게 확정되지 않은 경우가 많다.

따라서 다음 원칙을 적용한다.

* 불확실한 국경은 점선 또는 반투명 경계로 표시
* 추정 위치는 단일 지점이 아닌 추정 범위로 표현 가능
* 연대가 불확실하면 특정 연도가 아닌 기간으로 표시
* 논쟁 중인 출애굽 경로 등을 하나의 확정 경로처럼 단정하지 않음
* 복수 견해가 있을 경우 사용자가 견해를 전환할 수 있도록 설계

성경 시대의 국가, 지명, 이동 경로와 역사적 배경을 비교·검토하려는 사용자

## 6. 주요 사용자 시나리오

### 시나리오 1. 시대별 국가 변화 탐색

1. 사용자가 `학습 > 성경 역사 지도`에 진입한다.
2. 기본 화면에 성경 세계 전체 범위가 표시된다.
3. 시간 막대를 통일 왕국 시대로 이동한다.
4. 지도에 이스라엘 통일 왕국과 주변 국가가 표시된다.
5. 시간 막대를 분열 왕국 시대로 이동한다.
6. 지도에서 북이스라엘과 남유다의 분리를 확인한다.
7. 특정 국가를 선택하여 관련 왕, 사건, 성경 본문을 확인한다.

### 시나리오 2. 성경 지명 탐색

1. 사용자가 `니느웨`를 검색한다.
2. 지도 중심이 니느웨 위치로 이동한다.
3. 고대 지명, 현대 위치, 관련 국가와 시대가 표시된다.
4. 요나서 등 관련 성경 본문을 확인한다.
5. `성경에서 읽기`를 선택하여 해당 본문으로 이동한다.

### 시나리오 3. 이동 경로 확인

1. 사용자가 지도 유형에서 `바울의 전도여행`을 선택한다.
2. 1차, 2차, 3차 전도여행 경로가 구분되어 표시된다.
3. 경로상의 도시를 선택한다.
4. 해당 도시에서 발생한 사건과 사도행전 본문을 확인한다.

### 시나리오 4. 역사적 불확실성 확인

1. 사용자가 출애굽 경로를 선택한다.
2. 화면에 `경로에 여러 견해가 있습니다`라는 안내가 표시된다.
3. 사용자가 경로 견해 A와 B를 전환한다.
4. 각 견해의 출처와 설명을 확인한다.

## 7. 화면 구성

### 7.1 전체 구조

화면은 `시간 영역`, `지도 영역`, `정보 영역`의 세 켜로 구성한다. 지도는 항상 화면의 주인공이며, 나머지 요소는 지도를 가리지 않는 오버레이 또는 접이식 패널로 동작한다.

#### 데스크톱 (992px 이상)

```text
┌──────────────────────────────────────────────────────────┐
│ ◀ 이전 시대 │ ▶ 재생 │ 시간 막대 ─────────── │ 다음 시대 ▶ │  ← 시간 영역(상단 고정)
│            기원전 590년 · 분열 왕국 시대 / 바벨론 포로기      │
├──────────────┬───────────────────────────────┬───────────┤
│ 검색 ▢       │                               │ 장소 상세  │
│ 레이어 ▾     │                               │ 패널      │
│  □ 정치      │        성경 역사 지도           │ (선택 시   │
│  □ 장소      │                               │  열림,    │
│  □ 사건      │                               │  360px)   │
│  □ 경로      │                               │           │
│ 범례 ▾       │          ⓘ 스냅샷 안내         │           │
├──────────────┴───────────────────────────────┴───────────┤
│ 현재 시대 설명 · 출처 요약 · 데이터 상태 · 텍스트 목록 보기  │  ← 정보 영역
└──────────────────────────────────────────────────────────┘
```

* 좌측 컨트롤(검색·레이어·범례)은 지도 위에 겹치는 카드형 오버레이이며, 각 그룹은 개별 접기·펼치기가 가능하다.
* 장소 상세 패널은 우측에서 슬라이드로 열리는 사이드 패널이다. 열려 있는 동안에도 지도 조작이 가능해야 한다.
* 스냅샷 안내(7.3절)는 지도 하단 중앙의 배지로 상시 표시한다.

#### 모바일 (992px 미만)

```text
┌──────────────────────────┐
│ 검색 🔍          레이어 ▾ │  ← 상단 축약 컨트롤
│                          │
│       성경 역사 지도       │
│                          │
│      ⓘ 스냅샷 안내        │
│                          │
├──────────────────────────┤
│ ▶ │ 시간 막대 ──────────  │  ← 하단 고정(7.2절)
│ 기원전 590년 · 분열 왕국    │
└──────────────────────────┘

장소 선택 시: 화면 하단에서 바텀 시트가 올라옴
(1단: 요약 → 위로 끌면 2단: 전체 상세)
```

* 시간 막대는 하단 고정으로 엄지 조작 범위에 둔다.
* 범례·시대 설명·텍스트 목록 보기는 상시 노출하지 않고, 레이어 버튼과 같은 계층의 메뉴에서 호출한다.
* 지도 제스처(끌기·확대)와 페이지 스크롤이 충돌하지 않도록, 지도 영역은 화면 높이에 고정하고 페이지 자체는 스크롤을 갖지 않는다.

#### 영역별 책임

| 영역        | 구성 요소                       | 동작 원칙                          |
|-----------|-----------------------------|--------------------------------|
| 시간 영역     | 시간 막대, 재생, 시대 이동, 현재 연도·시대명 | 항상 노출. 데스크톱 상단 · 모바일 하단 고정     |
| 지도 영역     | 지도, 컨트롤 오버레이, 스냅샷 안내 배지     | 최대 면적 확보. 오버레이는 접을 수 있어야 함     |
| 상세 패널     | 장소·국가·사건·경로 상세(11장)         | 데스크톱 사이드 패널 · 모바일 2단 바텀 시트     |
| 정보 영역     | 시대 설명, 출처 요약, 데이터 상태        | 데스크톱 하단 바 · 모바일은 메뉴에서 호출       |

### 7.2 시간 막대

지도 상단에 가로형 시간 막대를 배치한다.

필수 동작:

* 왼쪽에서 오른쪽으로 이동하면 미래 시대로 이동
* 오른쪽에서 왼쪽으로 이동하면 과거 시대로 이동
* 드래그, 클릭, 키보드 방향키 지원
* 선택한 연도와 시대명을 동시에 표시
* 주요 시대를 눈금 또는 시대 버튼으로 표시
* 재생·일시정지 기능 제공
* 이전 시대·다음 시대 이동 버튼 제공
* 모바일에서는 화면 하단에 고정 가능

표시 예시:

```text
족장 시대 ─ 출애굽 ─ 사사 시대 ─ 통일 왕국 ─ 분열 왕국
          ─ 바벨론 포로기 ─ 페르시아 ─ 헬레니즘 ─ 로마 시대
```

시대 명칭은 8장의 시대 구분 표와 동일한 용어를 사용한다.

시대가 서로 중첩되는 구간(예: 분열 왕국 시대와 바벨론 포로기의 기원전 597~587/586년, 로마 시대와 사도 시대)은 눈금을 겹쳐 그리지 않는다. 시간 막대에는 대표 시대 하나만 순서대로 표시하고, 중첩 구간에서 특정 연도를 선택하면 해당 연도에 해당하는 시대들을 시대명 영역에 함께 표기한다(예: `기원전 590년 · 분열 왕국 시대 / 바벨론 포로기`).

### 7.3 연속 시간과 역사 스냅샷

사용자에게는 시간 막대가 연속적으로 이동하는 것처럼 보이지만, 국가 경계는 검수된 `역사 스냅샷`을 기준으로 변경한다.

예를 들어 사용자가 기원전 925년을 선택했더라도, 해당 시점의 경계 자료가 존재하지 않으면 다음과 같이 표시한다.

> 현재 지도는 기원전 930년경의 역사 자료를 기준으로 표시하고 있습니다.

이 방식으로 근거가 없는 연도별 경계를 임의로 생성하는 문제를 방지한다.

### 7.4 장소 상세 패널 동작

* 지도에서 장소·국가·경로를 선택하면 상세 패널이 열리고, 선택 대상은 지도에서 강조 표시한다.
* 데스크톱: 우측 사이드 패널(폭 약 360px). 패널이 열려도 지도 중심을 강제로 이동하지 않되, 선택 지점이 패널에 가려지면 가려지지 않는 위치로 지도를 부드럽게 보정한다.
* 모바일: 2단 바텀 시트. 1단(요약: 대표 명칭, 시대, 확실성 배지, `성경에서 읽기`)에서 위로 끌면 2단(11장의 전체 상세)으로 확장한다.
* 닫기: 닫기 버튼, 지도 빈 영역 선택, `Esc` 키 모두 지원한다.
* 선택 상태는 URL 쿼리에 반영하여(17.1절) 새로고침·공유 시 동일 화면을 재현한다.
* 패널 내부에서 다른 장소 링크(관련 사건의 장소 등)를 선택하면 패널 내용만 교체하고, 뒤로 가기로 이전 선택으로 돌아갈 수 있다.

### 7.5 지도 컨트롤과 범례

* 검색: 데스크톱은 좌측 상단 검색창, 모바일은 상단 검색 버튼 → 전체 화면 검색으로 전환. 결과 선택 시 지도 이동 + 상세 패널 열기(시나리오 2).
* 레이어: 9장의 레이어를 체크박스 그룹으로 제공한다. 기본값은 `역사 정치 + 성경 장소` 켜짐, `현대 국가 경계` 꺼짐(9.1절). 레이어 상태는 URL과 동기화한다.
* 범례: 10.3절의 경계 표현(실선·점선·반투명·사선)과 확실성 배지(13.3절)를 동일한 용어로 설명한다. 범례는 색상 견본과 함께 표식 모양을 병기하여 색각 이상 사용자도 구분할 수 있게 한다(19.2절).
* 시대가 바뀌어 방금 전까지 보이던 국가·지명이 사라지는 경우, 지도가 "비어 보이는" 혼란을 막기 위해 시대 전환 직후 1회 `기원전 722년 · 북이스라엘 멸망 이후` 같은 전환 요약 토스트를 표시한다.

### 7.6 화면 상태

| 상태       | 표시                                                        |
|----------|-----------------------------------------------------------|
| 최초 로딩    | 지도 골격 + 스켈레톤. 3초 이내 주요 콘텐츠 표시(19.1절)                      |
| 데이터 없음   | 선택 시대·영역에 데이터가 없으면 빈 지도 대신 안내 문구 + 가장 가까운 스냅샷 제안(16.9절)   |
| 범위 밖 연도  | `데이터 범위 밖 연도` 안내와 함께 가장 가까운 스냅샷으로 표시(16.9절)               |
| 불확실 데이터  | 확실성 배지·점선 경계·복수 견해 전환 버튼을 데이터와 같은 위치에 표시(4.2절, 13.3절)     |
| 오류       | 공통 오류 규격의 메시지를 지도 위 배너로 표시하고 재시도 버튼 제공                    |

* 텍스트 목록 보기(19.2절): 현재 화면에 표시 중인 국가·장소·사건을 표 형태로 제공하는 대체 화면이며, 정보 영역(데스크톱) 또는 메뉴(모바일)에서 진입한다.
* 다크 모드: 기존 학습 페이지와 동일하게 theme.css 시맨틱 토큰을 따르며, 지도 스타일도 라이트·다크 두 벌을 제공한다. 확실성 표현(점선·사선)은 두 테마에서 동일한 의미로 유지한다.

## 8. 시대 구분

다음 시대 구분은 초기 데이터 구축을 위한 기본안이며, 전문가 검수 후 확정한다.

| 시대        |          대략적인 범위 | 주요 콘텐츠                |
|-----------|-----------------:|-----------------------|
| 족장 시대     | 약 기원전 2000~1600년 | 아브라함, 이삭, 야곱, 가나안, 애굽 |
| 출애굽·정착 시대 |         연대 견해 상이 | 애굽, 시내산, 광야, 가나안 정착   |
| 사사 시대     | 약 기원전 1200~1020년 | 이스라엘 지파, 블레셋, 모압, 암몬  |
| 통일 왕국 시대  |  약 기원전 1020~930년 | 사울, 다윗, 솔로몬           |
| 분열 왕국 시대  | 약 기원전 930~587/586년 | 북이스라엘, 남유다, 아람, 앗수르   |
| 바벨론 포로기   | 약 기원전 597~538년 | 바벨론, 유다 포로 공동체        |
| 페르시아 시대   |  기원전 539/538~332년 | 페르시아 제국, 귀환, 예루살렘 재건  |
| 헬레니즘 시대   |      기원전 332~63년 | 알렉산더 제국과 후계 왕조        |
| 로마 시대       | 기원전 63년~서기 100년경 | 로마 지배, 헤롯 왕조, 예수님의 사역, 유대 전쟁 |
| 사도 시대      |     약 서기 30~100년 | 사도들의 활동과 초기 교회 확산     |

이 구분은 서로 배타적인 연대표가 아니다. 로마 시대와 사도 시대는 관점이 다른 중첩 구간이며, 분열 왕국 시대(종료: 기원전 587/586년)와 바벨론 포로기(시작: 기원전 597년) 역시 약 10년간 중첩된다. 중첩 구간의 화면 표시 규칙은 7.2절을 따른다.

분열 왕국 시대의 종료 연도는 남유다의 멸망을 기준으로 한 것이다. 북이스라엘은 기원전 722년경 사마리아 함락으로 먼저 멸망했고, 남유다는 기원전 587/586년경 예루살렘 함락으로 멸망했다. 바벨론 포로기는 기원전 597년의 첫 대규모 강제 이주에서 시작하여 기원전 587/586년 예루살렘 멸망 때 확대되었고, 기원전 539년 페르시아의 바벨론 정복과 기원전 538년경 귀환 허용을 전환점으로 본다.

족장 시대와 출애굽·정착 시대처럼 연대 견해가 나뉘는 항목은 특정 연도를 정답으로 고정하지 않는다.

## 10. 지도 표시 규칙

### 10.1 확대 수준별 표시

| 확대 수준 | 표시 정보                |
|-------|----------------------|

중요도가 낮은 지명은 축소하거나 숨기되, 검색과 상세 패널에서는 접근할 수 있어야 한다.

### 10.2 명칭 표시

각 장소는 다음 이름을 가질 수 있다.

* 한국어 대표 이름

* 고대 원어 이름
* 영문 표기
* 현대 지명
* 시대별 별칭

예시:

```text
니느웨
Nineveh
현대 위치: 이라크 모술 인근
소속 시대: 앗수르 제국
```

같은 장소의 명칭이 시대에 따라 변경되면 선택한 시대에 맞는 대표 이름을 지도에 표시한다.

### 10.3 경계 표현

* 역사적으로 비교적 명확함: 실선
* 대략적인 세력권: 반투명 면
* 추정 경계: 점선
* 견해가 나뉨: 사선 패턴 또는 복수 경계
* 현재 선택한 국가: 강조 외곽선

경계 스타일은 범례에서 동일한 용어로 설명하여, 사용자가 실선·점선·반투명 표현의 의미를 혼동하지 않도록 한다.

## 13. 역사 데이터 검증 정책

### 13.1 출처 원칙

모든 역사 지명, 경계, 사건과 연대 데이터는 출처를 보유해야 한다.

고대 지명 데이터의 기초 자료로는 다음과 같은 검증 가능한 데이터셋을 활용할 수 있다.

* Pleiades는 고대 장소와 공간에 관한 공동 연구 기반 지명 데이터베이스이며, 콘텐츠를 Creative Commons Attribution 3.0 라이선스로 제공한다. 다만 그리스·로마 세계의 자료 비중이 높으므로 성경 전체 지역을 단독으로 포괄하는 자료로 사용해서는 안 된다.
* World Historical Gazetteer는 시간과 언어에 따라 달라지는 역사적 장소 기록을 연결하기 위한 플랫폼이므로, 지명 변형과 시대별 명칭을 연결하는 보조 자료로 활용한다.
* 세계 기본 지도에는 여러 축척의 벡터·래스터 데이터를 제공하는 Natural Earth를 후보로 사용한다. Natural Earth 데이터는 공공 영역으로 제공되며, 세계·지역 수준의 기본 지형 구성에 적합하다.

외부 데이터는 그대로 노출하지 않고, 라이선스와 정확도를 확인한 뒤 elseeker 내부 검수 데이터로 변환한다.

연대와 표준 검증에는 다음 자료를 기준으로 삼는다.

* [Oxford History of the Holy Land: Israel and Judah](https://academic.oup.com/book/45676/chapter-abstract/398059551)
* [The Metropolitan Museum of Art: Cyrus and the Judean Diaspora](https://www.metmuseum.org/perspectives/cyrus-and-the-judean-diaspora)
* [Posen Library: The Roman Conquest of Judea](https://www.posenlibrary.com/guide/roman-conquest-judea)
* [Pleiades](https://pleiades.stoa.org/) 및 [Pleiades Credits](https://pleiades.stoa.org/credits)
* [World Historical Gazetteer](https://whgazetteer.org/about/)
* [Natural Earth: About](https://www.naturalearthdata.com/about/)
* [RFC 7946: The GeoJSON Format](https://www.rfc-editor.org/rfc/rfc7946)
* [OGC Web Map Service 1.3.0](https://docs.ogc.org/is/06-042/06-042.pdf)
* [W3C Time Ontology in OWL](https://www.w3.org/TR/owl-time/)

### 13.3 확실성 등급

| 등급          | 의미                   | 화면 표현            |
|-------------|----------------------|------------------|
| CONFIRMED   | 복수의 신뢰할 수 있는 자료에서 확인 | 별도 경고 없음         |
| PROBABLE    | 유력하지만 완전히 확정되지 않음    | `유력한 위치`         |

### 13.4 검수 프로세스

```text
자료 등록
→ 출처 및 라이선스 확인

→ 성경 본문 연결 검수
→ 역사·신학 검수
```

* DRAFT

승인 이후에도 출처 변경, 좌표 변경, 연대 변경처럼 해석에 영향을 주는 수정은 재검수 대상으로 처리한다.

## 14. 지도 데이터 표준

### 14.1 좌표계

* 원본 데이터 저장: WGS 84 기반 경위도 좌표(SRID 4326); 저장 필드와 축 순서를 스키마에 명시
* 웹 지도 렌더링: EPSG:3857 사용 가능
* 데이터 교환: RFC 7946 GeoJSON
* 공간 객체: Point, MultiPoint, LineString, MultiLineString, Polygon, MultiPolygon, GeometryCollection

RFC 7946 GeoJSON은 WGS 84 기반의 십진수 좌표를 `[경도, 위도]` 순서로 사용하며, 이는 OGC `CRS84`의 축 순서와 같다. EPSG:4326의 공식 축 정의는 위도·경도 순서이므로, 두 식별자를 축 순서까지 동일한 것으로 간주해서는 안 된다. GeoJSON 입출력에서는 항상 `[경도, 위도]` 순서를 적용한다.

공간 객체는 GeoJSON이 정의한 7개 geometry 타입을 사용한다. OGC Simple Features와 연계할 때는 LineString을 Curve 계열로, Polygon을 Surface 계열로 대응하되 GeoJSON 타입 이름을 임의로 바꾸지 않는다.

EPSG:3857은 웹 지도 시각화에 적합하지만 거리와 면적에 왜곡이 존재하므로, 역사적 거리 계산이나 면적 비교의 기준 좌표계로 사용하지 않는다.

### 14.2 시간 데이터

역사 데이터는 한 시점을 나타내는 값이 아니라 유효 기간으로 관리한다.

필수 값:

* 유효 시작 연도
* 유효 종료 연도
* 시작 연도 오차 범위
* 종료 연도 오차 범위
* 연대 확실성
* 시대 구분
* 적용 스냅샷

시간의 시점과 구간을 구분하는 구조는 W3C와 OGC의 공동 작업으로 개발된 OWL-Time 개념을 참고한다. OWL-Time은 시점, 구간, 지속 시간 및 시간적 선후 관계를 표현하기 위한 표준 어휘를 제공한다.

### 14.3 기원전·기원후 처리

사용자 화면에서는 역사 표기에 따라 다음과 같이 표시한다.

* 기원전 586년
* 서기 30년

화면에는 `0년`을 표시하지 않는다.

내부 연도와 API의 `year` 값은 프로젝트 표기법으로 통일한다. 기원전 n년은 `-n`, 서기 n년은 `n`으로 저장하고 `0`은 허용하지 않는다. 따라서 `year=-586`은 기원전 586년을 뜻한다. 이 규칙은 0년을 사용하는 천문학적 연도 표기와 다르므로 외부 라이브러리나 데이터셋과 연동할 때 공통 변환 모듈에서 보정한다. 두 연도 사이의 기간을 계산할 때도 0년이 없다는 점을 반영한다.

### 15.2 HistoricalSnapshot

7.3절의 `역사 스냅샷`을 나타낸다. 지도에 표시되는 국가 경계와 정치 지형은 항상 특정 스냅샷을 기준으로 한다. 하나의 시대 안에 복수의 스냅샷이 존재할 수 있다(예: 분열 왕국 시대 안의 기원전 930년경 스냅샷과 기원전 722년 이후 스냅샷).

```text
id
periodId
label
baseYear
validFromYear
validToYear
description
reviewStatus
displayOrder
```

* `baseYear`: 이 스냅샷이 근거로 삼는 대표 연도. 사용자가 임의 연도를 선택하면 해당 연도를 포함하는 시대에서 가장 적합한 스냅샷을 선택하고, 화면에 `기원전 930년경의 역사 자료 기준` 형태로 안내한다.
* `validFromYear`/`validToYear`: 스냅샷을 적용할 수 있는 연도 범위. 범위가 지정된 스냅샷이 있으면 단순히 대표 연도가 가까운 자료보다 우선한다.

* `validFromYear`/`validToYear`는 국가 자체의 존속 기간(검색·상세 패널용)이고, 지도에 어떤 경계를 그릴지는 항상 `snapshotId`가 결정한다. 두 값이 충돌할 경우 지도 표시는 스냅샷을 따른다.

## 16. API 초안

모든 조회 API는 화면 표시용 데이터와 함께 출처 요약, 확실성 등급, 적용 스냅샷 정보를 제공한다. 클라이언트가 별도 규칙을 추정하지 않도록 표시 문구와 상태값을 함께 내려주는 것을 원칙으로 한다.

### 16.1 시대 목록 조회

```http
GET /api/v1/bible-history/periods
```

### 16.2 특정 시점 지도 데이터 조회

```http
GET /api/v1/bible-history/map
    ?year=-586
    &zoom=5
    &bbox=minLon,minLat,maxLon,maxLat
    &layers=polity,place,event
```

파라미터 규칙:

* `year`: 14.3절의 연도 규약을 따른다(기원전 n년 = `-n`, `0` 불허).
* `bbox`: WGS 84 십진수 `[경도, 위도]` 순서의 `minLon,minLat,maxLon,maxLat` 4개 값.
* `layers`: `polity`, `place`, `event`, `route` 중 쉼표 구분 목록. 알 수 없는 값은 오류로 처리한다.

응답 항목:

* 현재 선택 연도
* 적용된 역사 스냅샷
* 국가 및 지역
* 장소
* 사건
* 경로
* 출처 요약
* 데이터 확실성

### 16.3 장소 상세 조회

```http
GET /api/v1/bible-history/places/{placeId}
```

### 16.4 국가·제국 상세 조회

```http
GET /api/v1/bible-history/polities/{polityId}
```

### 16.5 사건 상세 조회

```http
GET /api/v1/bible-history/events/{eventId}
```

### 16.6 이동 경로 목록 조회

지도 유형 선택 UI(시나리오 3의 `바울의 전도여행` 선택)는 이 목록을 사용한다. 같은 `routeGroupId`의 견해들은 하나의 항목으로 묶고 기본 견해를 함께 내려준다.

```http
GET /api/v1/bible-history/routes
    ?routeType=missionary-journey
```

### 16.7 이동 경로 상세 조회

```http
GET /api/v1/bible-history/routes/{routeId}
```

응답에는 같은 `routeGroupId`에 속한 대안 견해 목록을 포함하여, 클라이언트가 견해 전환 UI를 추가 호출 없이 구성할 수 있도록 한다.

### 16.8 통합 검색

```http
GET /api/v1/bible-history/search
    ?keyword=니느웨
    &page=0
    &size=20
```

검색 결과는 페이지네이션을 적용하며, 전체 건수와 다음 페이지 존재 여부를 함께 반환한다.

### 16.9 오류 및 빈 결과 계약

* 요청 `year`가 서비스 데이터 범위를 벗어나면 오류가 아니라, 가장 가까운 스냅샷과 함께 `데이터 범위 밖 연도` 상태를 반환한다. 클라이언트는 이 상태를 안내 문구로 표시한다.
* 잘못된 파라미터(형식 오류, 허용되지 않는 layer 값, `year=0` 등)는 기존 공통 오류 규격(`ServiceError` → `GlobalExceptionHandler` → `ErrorResponse`)을 따른다.
* 조회 결과가 없는 지역·시대는 빈 컬렉션과 함께 적용 스냅샷 정보를 반환한다.

### 16.10 관리자 API

18장의 관리자 기능은 기존 관리자 API 컨벤션(`/api/v1/admin/**`)을 따라 `/api/v1/admin/bible-history/**` 아래에 구성하며, 관리자 인증·권한 검증(19.3절)을 적용한다. 세부 명세는 관리자 기능 구현 단계에서 별도 정의한다.

## 17. 기술 구성 권장안

### 17.1 프론트엔드

* 인터랙티브 지도 렌더링 라이브러리
* 벡터 타일 또는 GeoJSON 기반 레이어
* 반응형 웹
* 지도 레이어 상태 관리
* 시간 막대 상태와 URL 동기화

MapLibre GL JS는 브라우저에서 WebGL을 이용해 벡터 타일 기반 지도를 렌더링하고 스타일 문서를 통해 지도 표현을 제어할 수 있으므로 구현 후보로 적합하다.

기존 프론트엔드 컨벤션(번들러 없는 vanilla ES6 모듈 + WebJars)과의 정합을 위해 다음을 적용한다.

* MapLibre GL JS는 WebJars로 제공되지 않으므로, 배포 파일(JS·CSS)을 `static/vendor/` 아래에 자체 호스팅하고 버전을 파일 경로 또는 `?v=` 쿼리로 관리한다. 외부 CDN 의존은 두지 않는다.
* 시간 막대·레이어·선택 장소 상태와 URL 동기화는 이 프로젝트에서 가장 큰 클라이언트 상태를 다루게 되므로, 프레임워크 도입 없이 단일 상태 객체 + 이벤트 구독 패턴(기존 페이지들의 클래스 기반 구조 확장)으로 설계하고, URL 반영은 `URLSearchParams` + `history.replaceState`로 처리한다.

### 17.2 백엔드

* Kotlin
* Spring Boot
* PostgreSQL
* PostGIS
* Redis 선택 적용
* 지도 데이터 관리용 관리자 API

PostGIS는 PostgreSQL에서 OGC Geometry 모델에 따른 `geometry`, `geography` 공간 타입과 공간 연산을 제공하므로 국가 경계, 경로와 지점 데이터를 관리하기에 적합하다.

기존 환경과의 전환 비용은 다음과 같이 처리한다.

* 로컬·운영 모두 PostgreSQL을 사용하므로 PostGIS 확장 활성화(`CREATE EXTENSION postgis`)로 도입 가능하다.
* 통합 테스트는 Testcontainers PostgreSQL 이미지를 PostGIS 포함 이미지(`postgis/postgis`)로 교체해야 한다. 기존 `IntegrationTest` 기반 테스트가 동일 컨테이너를 공유하므로 전체 테스트에 영향이 없는지 확인한다.
* JPA에서 공간 타입을 다루기 위해 Hibernate Spatial과 JTS Geometry 매핑 의존성을 추가한다.

### 17.3 지도 데이터 제공 방식

초기 데이터 규모가 작을 때:

* API에서 GeoJSON 반환
* CDN 캐시 적용

데이터 규모가 증가한 이후:

* 벡터 타일 적용
* 확대 수준별 데이터 단순화
* 타일 서버 또는 정적 타일 저장소 적용

* 충분한 명도 대비 적용

### 19.3 보안

* 관리자 API 인증·권한 검증
* GeoJSON 업로드 파일 검증
* 외부 HTML과 스크립트 입력 차단
* 데이터 변경 이력 보존
* 승인되지 않은 콘텐츠 운영 노출 방지

### 19.4 데이터 무결성

* 유효 시작 연도가 종료 연도보다 클 수 없음
* 모든 공개 데이터에 한 개 이상의 출처 필수
* 삭제 대신 비활성화 및 버전 보관
* 경계 데이터의 Geometry 유효성 검사
* 성경 본문 링크 유효성 검사

MVP는 지도 엔진 검증보다 학습 흐름 검증을 우선한다. 따라서 국가 경계의 세밀함보다 주요 장소, 사건, 성경 본문 연결의 완성도를 우선한다.

## 24. 완료 기준

다음 조건을 모두 충족하면 MVP 개발이 완료된 것으로 본다.

1. 사용자가 시간 막대를 과거와 미래 방향으로 이동할 수 있다.
2. 선택한 시대에 따라 국가·지역·지명이 동적으로 변경된다.
3. 현재 선택한 연도와 적용된 역사 스냅샷을 확인할 수 있다.
4. 지도에서 장소와 국가를 선택하여 상세 정보를 확인할 수 있다.
5. 장소 상세에서 관련 성경 본문으로 이동할 수 있다.
6. 동일 장소의 고대 지명과 현대 지명을 함께 확인할 수 있다.
7. 추정·논쟁 중인 데이터가 확정 데이터와 구분되어 표시된다.
8. 모든 운영 데이터에 출처와 검수 정보가 존재한다.
9. PC와 모바일 환경에서 핵심 기능을 사용할 수 있다.
10. 출처가 없거나 승인되지 않은 데이터는 운영 화면에 표시되지 않는다.
11. 시간 막대, 검색, 레이어 선택은 키보드로도 조작할 수 있다.
12. 지도 정보를 대체할 텍스트 목록 또는 상세 패널을 통해 주요 내용을 확인할 수 있다.

## 25. 최종 기능 방향

성경 역사 지도는 단순히 고대 지명을 지도 위에 표시하는 기능이 아니라 다음 세 요소를 연결하는 elseeker의 핵심 학습 기능으로 발전시킨다.

```text
성경 본문
＋
시간의 흐름
＋
역사적 공간
```

사용자는 성경을 읽다가 지도를 열고, 지도에서 다시 성경 본문으로 돌아갈 수 있어야 한다.

또한 역사적으로 불확실한 내용을 숨기거나 하나의 정답으로 단정하지 않고, 확실성 수준과 출처를 함께 제공함으로써 신뢰할 수 있는 성경 학습 경험을 지향한다.
