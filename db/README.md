# db

DB 스키마·데이터 스크립트를 모아 둔 디렉토리입니다. **마이그레이션 도구(Flyway/Liquibase)는 쓰지
않습니다.** 모든 스크립트는 사람이 직접 적용합니다.

`src/` 밖에 두는 이유는 이 파일들이 **애플리케이션 런타임에 전혀 쓰이지 않기 때문**입니다.
`spring.sql.init` 은 꺼져 있고 `defer-datasource-initialization` 도 주석 처리돼 있어 자동 로드되지
않는데, `src/main/resources/` 에 두면 `bootJar` 와 컨테이너 이미지에 그대로 포장됩니다.
(시드 데이터만 6.9 MB 였습니다.)

## 구조

| 디렉토리 | 내용 | 적용 시점 |
|---|---|---|
| `schema/` | 테이블 정의 (테이블 1개 = 파일 1개) | 해당 기능 배포 **직전** |
| `migration/` | 1회성 스키마·데이터 변경 스크립트 | 해당 기능 배포 **직전**, 1회만 |
| `seed/` | 정적 시드·참조 데이터 (성경 본문, 사전, 퀴즈, 퍼즐) | 최초 구축 시 / 필요할 때 |

파일을 테이블명으로 찾게 되므로 `schema/` 는 모듈별 하위 디렉토리 없이 평면 구조로 둡니다.

## 적용 방법

```bash
psql "$DATABASE_URL" -f db/schema/apple_notification_audit.sql
```

Supabase 접속 정보는 [.claude/rules/tech-stack.md](../.claude/rules/tech-stack.md) 를 참고하세요.
(직접 호스트는 IPv6 전용이라 **세션 풀러 호스트 + 5432 + `sslmode=require`** 를 써야 합니다.)

## 작성 규칙

`schema/` 스크립트는 **여러 번 실행해도 안전해야 합니다.** 운영 반영 여부를 기억에 의존하지 않기
위해서입니다.

- `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`
- 제약 추가는 `DROP CONSTRAINT IF EXISTS` 후 `ADD CONSTRAINT`
- 파일 상단에 헤더 주석 블록 — 테이블명, 목적, 매핑 엔티티, 대상 DB, (있으면) 설계 문서 경로
- 테이블과 자명하지 않은 컬럼에는 한국어 `COMMENT ON`
- 타임스탬프 컬럼은 **`TIMESTAMP(6)`** (`TIMESTAMPTZ` 아님).
  `spring.jpa.properties.hibernate.jdbc.time_zone: UTC` 가 설정돼 있어 Hibernate 가 `Instant` 를
  UTC 로 변환해 기록합니다. 자세한 내용은
  [.claude/rules/time-and-locale.md](../.claude/rules/time-and-locale.md) 참고.
- `id` 는 `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` (`@GeneratedValue(IDENTITY)` 대응)

`migration/` 스크립트는 1회성이므로 멱등할 필요는 없지만, 무엇을 왜 바꾸는지 헤더에 적습니다.

## 주의

- **테스트 프로파일만 `ddl-auto: update`** 입니다. 통합 테스트는 Testcontainers 가 띄운 DB 에
  Hibernate 가 스키마를 자동 생성하므로, 여기 스크립트를 적용하지 않아도 통과합니다.
  **즉 이 디렉토리의 스크립트를 빠뜨려도 테스트는 초록불입니다.** 운영 반영은 별도로 챙겨야 합니다.
- 그 결과 Hibernate 가 만든 테스트 스키마와 이 스크립트가 만든 운영 스키마가 **완전히 같지는
  않습니다**(예: Hibernate 는 `Instant` 를 `timestamptz` 로 생성). 두 표현 모두 `Instant` 와
  정상 동작하지만, 컬럼 타입에 의존하는 SQL 을 쓸 때는 운영 스키마를 기준으로 삼으세요.
- `seed/` 는 자동 실행되지 않습니다. 초기 데이터 구축용 참고 자료입니다.
